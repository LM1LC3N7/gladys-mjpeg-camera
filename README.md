# gladys-mjpeg-camera

[Gladys Assistant](https://gladysassistant.com) external integration for
**MJPEG and snapshot IP cameras** (ESP32-CAM, older IP cameras, webcams
behind motion, motionEye or mjpg-streamer): camera images in Gladys without
RTSP, on the local network. For RTSP cameras, use the RTSP camera
integration built into Gladys. **Not affiliated with any camera maker.**

User documentation: [docs/en.md](docs/en.md) · [docs/fr.md](docs/fr.md).

## How it works

```
Gladys ⇄ SDK ⇄ src/app.js (MjpegCameraApp)
                 ├─ src/http.js     one capture: node:http(s), redirects, deadline, auth retry
                 ├─ src/auth.js     Basic, Digest (RFC 7616) (pure)
                 ├─ src/mjpeg.js    the first JPEG of a snapshot or a multipart stream (pure)
                 ├─ src/jpeg.js     JPEG markers: size, end of the image (pure)
                 ├─ src/image.js    the 150 KB camera image, downscaled with jpeg-js if needed
                 ├─ src/devices.js  devices, transport badges (pure)
                 └─ src/triggers.js health -> camera_offline / camera_online (pure)
```

- **Discovery** offers one camera device (a `camera`/`image` feature) per
  address of the `cameras` field.
- **Images**: every `refresh_seconds` (10 by default, 5 at least, 0 for on
  demand only) each created camera is captured and its image published with
  `publishCameraImage`; `onGetImage` answers the live view with a fresh
  capture. A stream is read up to its first complete frame, then the
  connection is closed.
- **Authentication**: credentials are sent only after a 401, as Digest when
  the camera offers it (MD5, SHA-256, SHA-512-256, `-sess`, `qop=auth` or
  none), Basic otherwise; the answered challenge is kept for the next
  captures.
- **Frames over 150 KB** (the core's bound, prefix included) are halved and
  re-encoded at quality 75 with `jpeg-js` until they fit.

## Development

```bash
npm install
npm test                                        # node --test, no network
npm run lint && npm run format:check
npx github:GladysAssistant/integration-store .  # store admission checks
```

The tests run the HTTP client against a fake camera listening on
127.0.0.1 (snapshot, multipart streams with and without `Content-Length`,
Basic, Digest, redirects, an old firmware's LF-only headers); the JPEG
fixtures are generated by the tests.

## Releasing

**Actions → Release → Run workflow** (patch / minor / major): bumps the
version in `package.json` and the manifest, rolls `CHANGELOG.md`, tags, builds
the multi-arch image to GHCR and publishes the GitHub Release.
